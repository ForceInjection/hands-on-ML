# 基于内容的推荐：特征工程与向量检索

在 [01\_推荐系统综述.md](01_推荐系统综述.md) 中，我们介绍了推荐系统的**多路召回**架构。**基于内容的推荐（Content-Based Recommendation, CB）** 通常是其中最基础、最稳定的一路召回策略。

它的核心逻辑非常直观：**如果你喜欢物品 A，而物品 B 在内容属性上与 A 相似，那么你很可能也喜欢 B。**

与协同过滤依赖“用户-物品交互矩阵”不同，CB 仅依赖**物品本身的特征**（如文本、图像、标签）。这使得它天然具备解决**物品冷启动（Cold Start）**问题的能力——只要新文章一发布，有了标题和正文，系统就能立即将其推荐给感兴趣的用户，而无需等待第一批用户的点击。

本章将从特征工程的视角出发，详解如何构建物品画像（Item Profile）与用户画像（User Profile），并探讨如何利用向量检索技术实现大规模实时推荐。

---

## 1. 核心原理：画像与匹配

基于内容的推荐可以被形式化为一个**向量空间模型（Vector Space Model）**问题。本章将详细拆解该模型的三个关键步骤：如何将物品转化为向量（物品画像）、如何量化用户偏好（用户画像）、以及如何度量二者之间的匹配程度（相似度计算）。

### 1.1 物品画像

物品画像是将非结构化或半结构化的物品信息转化为计算机可处理的结构化向量的过程。

$$
\text{Profile}(i) = [x_1, x_2, ..., x_n]
$$

常见的特征类型及处理方法：

- **结构化特征**：
  - **类别型**（如电影流派）：One-Hot Encoding, Multi-Hot Encoding。
  - **数值型**（如价格、时长）：归一化（Min-Max Scaling）、分箱（Binning）。
- **非结构化特征**：
  - **文本**（如简介、评论）：TF-IDF, Word2Vec, BERT Embedding。
  - **图像**（如海报、封面）：CNN (ResNet, VGG) 提取的倒数第二层全连接层向量。
  - **音频**（如音乐）：MFCC, Spectrogram CNN。

### 1.2 用户画像

用户画像是用户偏好的向量化表达。最简单的构建方式是基于用户历史行为的**加权平均**。

$$
\text{Profile}(u) = \frac{1}{|I_u|} \sum_{i \in I_u} w_{ui} \cdot \text{Profile}(i)
$$

其中 $I_u$ 是用户 $u$ 喜欢的物品集合，$w_{ui}$ 是行为权重（例如：点击=1，收藏=2，购买=5）。此外，通常引入**时间衰减因子**，让近期的行为权重更高。

### 1.3 相似度计算

推荐过程即计算用户向量与所有候选物品向量的相似度（通常使用余弦相似度），并返回 Top-K。

$$
\text{Score}(u, i) = \cos(\vec{u}, \vec{i}) = \frac{\vec{u} \cdot \vec{i}}{||\vec{u}|| \cdot ||\vec{i}||}
$$

## 2. 示例计算：手工算一次“内容推荐”

为了更直观地理解上述公式，我们通过一个极简案例来手工演算一遍推荐流程。

假设我们有三部电影，用三个维度（动作 Action、喜剧 Comedy、爱情 Romance）来表示其内容特征：

| 电影名            | Action | Comedy | Romance | 备注         |
| :---------------- | :----: | :----: | :-----: | :----------- |
| 电影 A            |   1    |   1    |    0    | 动作喜剧     |
| 电影 B            |   0    |   1    |    1    | 浪漫喜剧     |
| **电影 C (候选)** | **1**  | **0**  |  **1**  | **动作爱情** |

**场景假设**：用户历史行为中喜欢 **电影 A** 和 **电影 B**。现在我们要判断是否应该向用户推荐 **电影 C**。

### 第一步：构建用户画像 (User Profile)

我们采用最简单的**平均法**来构建用户画像。

$$
\vec{User} = \frac{\vec{A} + \vec{B}}{2} = \frac{[1, 1, 0] + [0, 1, 1]}{2} = \frac{[1, 2, 1]}{2} = [0.5, 1.0, 0.5]
$$

这意味着，该用户的偏好是：最喜欢“喜剧”（权重 1.0），其次是“动作”和“爱情”（权重均为 0.5）。

### 第二步：计算相似度

现在计算**用户画像**与**候选电影 C** $[1, 0, 1]$ 之间的余弦相似度。

1. **计算点积 (Dot Product)**:

   $$
   \vec{User} \cdot \vec{C} = (0.5 \times 1) + (1.0 \times 0) + (0.5 \times 1) = 0.5 + 0 + 0.5 = 1.0
   $$

2. **计算模长 (Magnitude)**:

   $$
   ||\vec{User}|| = \sqrt{0.5^2 + 1.0^2 + 0.5^2} = \sqrt{0.25 + 1 + 0.25} = \sqrt{1.5} \approx 1.225
   $$

   $$
   ||\vec{C}|| = \sqrt{1^2 + 0^2 + 1^2} = \sqrt{2} \approx 1.414
   $$

3. **计算余弦相似度 (Cosine Similarity)**:
   $$
   \text{Score} = \frac{1.0}{1.225 \times 1.414} = \frac{1.0}{1.732} \approx \mathbf{0.577}
   $$

### 结论

相似度约为 0.58。这是一个中等偏上的分数，意味着电影 C 与该用户的兴趣有一定重合度（主要是动作和爱情元素），但缺少用户最喜欢的“喜剧”元素。

## 3. 工程实践：基于 TF-IDF 的电影推荐 Pipeline

本节将使用 `scikit-learn` 构建一个完整的基于剧情简介（文本）的电影推荐 Pipeline。

### 3.1 数据集准备

假设我们有一个包含电影 ID、标题和剧情简介的小型数据集。

```python
import pandas as pd
import numpy as np
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import linear_kernel # 用于计算余弦相似度（对于归一化向量等同于点积）

# 1. 模拟数据
data = {
    'id': [1, 2, 3, 4, 5],
    'title': ['The Matrix', 'John Wick', 'Toy Story', 'Finding Nemo', 'Interstellar'],
    'plot': [
        'A computer hacker learns from mysterious rebels about the true nature of his reality and his role in the war against its controllers.',
        'An ex-hitman comes out of retirement to track down the gangsters that killed his dog and took everything from him.',
        'A cowboy doll is profoundly threatened and jealous when a new spaceman figure supplants him as top toy in a boy\'s room.',
        'After his son is captured in the Great Barrier Reef and taken to Sydney, a timid clownfish sets out on a journey to bring him home.',
        'A team of explorers travel through a wormhole in space in an attempt to ensure humanity\'s survival.'
    ]
}

df = pd.DataFrame(data)
```

### 3.2 构建 TF-IDF 矩阵

TF-IDF（Term Frequency-Inverse Document Frequency）能有效抑制常见词（如 "the", "is"）的权重，突显关键词（如 "hacker", "space"）。

```python
# 2. 特征工程 Pipeline
# stop_words='english': 过滤英语停用词
tfidf = TfidfVectorizer(stop_words='english')

# 构建物品画像矩阵 (Item Profile Matrix)
# 每一行代表一部电影的 TF-IDF 向量
tfidf_matrix = tfidf.fit_transform(df['plot'])

print("TF-IDF Matrix Shape:", tfidf_matrix.shape)
# 输出: (5, N_features)，N_features 是词汇表大小
```

### 3.3 推荐服务类封装

为了模拟生产环境，我们将推荐逻辑封装为一个类。

```python
class ContentBasedRecommender:
    def __init__(self, item_vectors, items_df):
        self.item_vectors = item_vectors
        self.items_df = items_df

    def get_recommendations(self, item_title, top_k=2):
        """
        场景 A：Item-to-Item 推荐
        输入用户喜欢的一部电影，推荐相似电影
        """
        # 1. 找到输入电影的索引
        idx = self.items_df.index[self.items_df['title'] == item_title].tolist()[0]

        # 2. 计算该电影与所有其他电影的余弦相似度
        # linear_kernel 计算点积。由于 TF-IDF 向量通常已 L2 归一化，点积等同于余弦相似度，且速度更快。
        cosine_sim = linear_kernel(self.item_vectors[idx:idx+1], self.item_vectors).flatten()

        # 3. 获取 Top-K 索引 (排除自身)
        sim_scores = list(enumerate(cosine_sim))
        sim_scores = sorted(sim_scores, key=lambda x: x[1], reverse=True)
        sim_indices = [i[0] for i in sim_scores[1:top_k+1]]

        return self.items_df.iloc[sim_indices][['title', 'plot']]

    def get_user_recommendations(self, user_liked_titles, top_k=2):
        """
        场景 B：User-to-Item 推荐
        基于用户历史喜欢的电影列表，构建用户画像向量，推荐电影
        """
        # 1. 获取用户喜欢的电影的索引
        indices = self.items_df.index[self.items_df['title'].isin(user_liked_titles)].tolist()

        if not indices:
            return "No valid items found."

        # 2. 构建用户画像向量 (User Profile Vector)
        # 简单策略：计算用户喜欢的电影向量的平均值
        user_profile = np.asarray(self.item_vectors[indices].mean(axis=0))

        # 3. 计算用户向量与所有物品向量的相似度
        cosine_sim = linear_kernel(user_profile, self.item_vectors).flatten()

        # 4. 获取 Top-K 结果 (需要排除用户已经看过的电影)
        sim_scores = list(enumerate(cosine_sim))
        sim_scores = sorted(sim_scores, key=lambda x: x[1], reverse=True)

        # 过滤掉已看过的
        recommendations = []
        for i, score in sim_scores:
            if i not in indices:
                recommendations.append(i)
            if len(recommendations) >= top_k:
                break

        return self.items_df.iloc[recommendations][['title', 'plot']]

# 初始化推荐服务
recommender = ContentBasedRecommender(tfidf_matrix, df)

# 测试 1：Item-to-Item
print("\n--- 场景 A: 基于 'The Matrix' 的相似推荐 ---")
print(recommender.get_recommendations('The Matrix'))

# 测试 2：User-to-Item (用户喜欢 Matrix 和 Inception 类型的科幻片)
# 假设用户喜欢 'The Matrix' 和 'Interstellar'
print("\n--- 场景 B: 基于用户画像 (喜欢 Matrix + Interstellar) 的推荐 ---")
print(recommender.get_user_recommendations(['The Matrix', 'Interstellar']))
```

## 4. 大规模系统中的挑战：向量检索

在上述示例中，我们计算了 query 向量与**所有** item 向量的相似度（Exact Search）。其时间复杂度为 $O(N \cdot D)$，其中 $N$ 是物品数量，$D$ 是向量维度。

当 $N$ 达到百万甚至亿级别时，线性扫描是不可接受的。生产环境中通常使用 **ANN (Approximate Nearest Neighbor)** 算法来加速检索。

### 4.1 常用 ANN 算法

1. **基于树的方法**：如 KD-Tree，但在高维空间下效率退化。
2. **基于哈希的方法**：如 LSH (Locality Sensitive Hashing)。
3. **基于图的方法**：如 **HNSW (Hierarchical Navigable Small World)**。
   - **原理一句话**：构建多层图结构，上层图用于快速跳跃定位大概区域，下层图用于精细查找，类似“跳表”思想。
   - **地位**：目前工业界最主流的算法，兼顾效率与精度。
4. **基于量化的方法**：如 PQ (Product Quantization)，通过压缩向量降低内存占用。

### 4.2 工具链

- **Faiss (Facebook AI Similarity Search)**：最强劲的向量检索库，支持 GPU 加速，内置了 HNSW、IVF 等多种索引。
- **Milvus / Zilliz**：开源向量数据库，提供云原生服务。
- **Elasticsearch (Dense Vector)**：ES 也增加了对向量检索的支持。

## 5. 优缺点与适用场景

基于内容的推荐算法在工业界应用广泛，但并非万能。在决定是否采用该策略前，我们需要辩证地评估其优势与局限性，并明确其最佳适用场景。

### 5.1 优点 (Pros)

1. **无冷启动问题 (No Cold Start)**：只要物品有属性（如标题、标签），一旦入库即可被推荐，无需等待用户交互数据。
   - _对比 CF_：协同过滤必须等有用户行为后才能推荐。
2. **可解释性强 (Explainable)**：可以明确告知用户：“因为你看了动作片 A，所以推荐动作片 B”。
3. **用户独立性**：推荐结果仅依赖当前用户的偏好，不受其他用户行为（如刷单）的影响。

### 5.2 缺点 (Cons)

1. **缺乏新颖性 (Serendipity)**：容易陷入**信息茧房 (Information Cocoon)**。系统倾向于不断推荐与用户历史偏好高度相似的内容，用户很难发现新领域的兴趣。
   - _对比 CF_：协同过滤通过“相似的人”可以发现用户潜在的新兴趣（如张三发现了新大陆，推荐给你）。
2. **特征工程瓶颈**：推荐效果高度依赖于物品特征提取的质量。对于难以提取特征的多媒体内容，效果受限（虽然深度学习缓解了这个问题）。

---

## 6. 总结

基于内容的推荐是构建推荐系统的“第一块积木”。它保证了推荐系统的**底线体验**（至少推荐的东西是相关的），并解决了新物品的分发问题。

在现代架构中，Content-Based 往往作为**多路召回**中的一路，与协同过滤互补：

- **协同过滤**负责发现惊喜和热门趋势；
- **内容推荐**负责保证相关性和覆盖长尾物品。
