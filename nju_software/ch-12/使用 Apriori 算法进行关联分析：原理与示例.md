# 使用 Apriori 算法进行关联分析：原理与示例

## 一、什么是关联分析？

关联分析（Association Analysis）是数据挖掘中的一种常用方法，用于发现事务数据中项之间的有趣关系。它最著名的应用场景是“购物篮分析”（Market Basket Analysis），比如：

> 如果顾客购买了牛奶和面包，那么他们很可能也会购买黄油。

这种“如果...那么...”的模式可以帮助零售商优化商品陈列、制定捆绑促销策略等。

---

## 二、Apriori 算法简介

Apriori 是一种经典的关联规则挖掘算法，它的核心思想是：

> **“一个项集是频繁的，其所有子集也一定是频繁的。”**

基于这个“先验知识”，Apriori 采用逐层扩展（level-wise）的方式，逐步构造更大的频繁项集，同时剪枝掉不可能的项集，减少计算量。

### 2.1 常用术语

* **项（Item）**：事务中的一个元素，如“牛奶”
* **项集（Itemset）**：一组项，如{牛奶, 面包}
* **支持度（Support）**：某个项集在所有事务中出现的频率
* **置信度（Confidence）**：某个规则的可信度，如从{牛奶}推出{面包}的概率
* **提升度（Lift）**：衡量规则强度是否优于随机猜测的指标

---

### 2.2 Apriori 算法步骤详解

1. **设定最小支持度（min\_support）**
   用户预先设定一个最小支持度阈值，算法只保留在数据集中出现频率不低于该阈值的项集，避免挖掘出无意义或偶然的规则。

2. **生成频繁 1 项集（L1）**
   对所有单个项统计其在事务中的出现频率，保留支持度 ≥ 最小支持度的项，作为频繁 1 项集。

3. **候选 k 项集生成（Ck）**
   根据频繁 (k-1) 项集 L(k-1)，进行自连接（self-join）生成候选 k 项集 Ck。举例：

   * 由 L2 = {AB, AC} 可生成 C3 候选项集 ABC。
   * 不会将 AB 与 AD 合并为 ABD，因为 BC 不在 L2 中，不满足剪枝条件。

4. **剪枝（Pruning）**
   对候选项集中每个项集的所有 (k-1) 子集进行检查，如果其中有任意一个不在 L(k-1) 中，说明该项集不可能频繁，予以删除。

5. **扫描数据集，计算支持度，构建 Lk**
   扫描整个事务数据库，统计每个候选项集 Ck 的出现次数，计算支持度，保留那些支持度 ≥ 最小支持度的项集作为频繁项集 Lk。

6. **重复步骤 3–5，直到没有新的频繁项集产生为止。**

7. **生成关联规则**
   从所有频繁项集中，挖掘满足最小置信度（min\_confidence）要求的关联规则。例如，从频繁项集 {A, B} 可生成：

   * A → B
   * B → A
     并计算各自的置信度和提升度，筛选出最有价值的规则。

## 三、用一个例子讲清楚 Apriori

我们来看一个如下的例子，共 6 条交易记录：

| 事务ID | 商品 |
| ---- | ---------- |
| T1   | 牛奶, 面包, 饼干 |
| T2   | 牛奶, 面包     |
| T3   | 面包, 饼干     |
| T4   | 牛奶, 饼干     |
| T5   | 牛奶, 面包, 饼干 |
| T6   | 面包         |

### 第一步：设定最小支持度阈值

设定最小支持度 = 50%（即至少在 6 条事务中出现 3 次）

---

### 第二步：频繁 1 项集（L1）

遍历所有事务，统计每个商品的出现次数：

| 项  | 计数 | 支持度 | 是否保留 |
| --- | --- | ----------- | ---- |
| 牛奶 | 4  | 4/6 ≈ 66.7% | ✅    |
| 面包 | 5  | 5/6 ≈ 83.3% | ✅    |
| 饼干 | 4  | 4/6 ≈ 66.7% | ✅    |

全部保留，构成频繁 1 项集 L1。

---

### 第三步：生成候选 2 项集（C2）并筛选频繁 2 项集（L2）

C2 候选项集是 L1 中两两组合的结果：

| 项集 | 计数 | 支持度 | 是否保留 |
| -------- | --- | --------- | ---- |
| {牛奶, 面包} | 3  | 3/6 = 50% | ✅    |
| {牛奶, 饼干} | 3  | 3/6 = 50% | ✅    |
| {面包, 饼干} | 3  | 3/6 = 50% | ✅    |

全部支持度达到阈值，保留为频繁 2 项集 L2。

---

### 第四步：生成候选 3 项集（C3）并筛选频繁 3 项集（L3）

C3 从 L2 中能组合出的 3 项集：

* 候选项集：{牛奶, 面包, 饼干}
* 子集有：{牛奶, 面包}, {牛奶, 饼干}, {面包, 饼干}（全部在 L2 中，保留）

| 项集 | 计数 | 支持度 | 是否保留  |
| ------------ | --- | ----------- | ----- |
| {牛奶, 面包, 饼干} | 2  | 2/6 ≈ 33.3% | ❌（丢弃） |

不满足支持度阈值，C3 为空，算法终止频繁项集挖掘。

---

### 第五步：生成关联规则

从 L2（频繁 2 项集）中挖掘满足最小置信度（如 60%）的规则。

以 {牛奶, 面包} 为例：

* 牛奶 → 面包，置信度 = Count({牛奶, 面包}) / Count(牛奶) = 3 / 4 = 75% ✅
* 面包 → 牛奶，置信度 = 3 / 5 = 60% ✅

其他规则计算类似：

| 规则      | 支持度 | 置信度 | 是否保留 |
| ------- | --- | --- | ---- |
| 牛奶 → 面包 | 50% | 75% | ✅    |
| 面包 → 牛奶 | 50% | 60% | ✅    |
| 牛奶 → 饼干 | 50% | 75% | ✅    |
| 饼干 → 牛奶 | 50% | 75% | ✅    |
| 面包 → 饼干 | 50% | 60% | ✅    |
| 饼干 → 面包 | 50% | 75% | ✅    |
