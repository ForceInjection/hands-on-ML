## 1. 核心概念 —— 特征工程的定义、边界与价值

本章将厘清特征工程的定义，划定其与数据工程的边界，并提出一个以“可复现、可回滚”为核心的最小工程闭环。

### 1.1 定义（Definition）

特征工程是把原始数据 $X$ 转换为模型可消费且与任务相关的表示（representation）$Z=\phi(X)$ 的过程。其目标是提升泛化性能、稳定性与可解释性，而不是只在训练集上获得更高指标。

在工程实践中，函数 $\phi$ 的构建通常包含以下四个核心维度，它们共同构成了特征处理的完整视图：

- **特征构造 (Construction)**：旨在基于领域知识挖掘原始数据中未直接表达的信息（即“无中生有”）。例如：从“时间戳”推导出“是否周末”；从“长”和“宽”计算出“面积”。
- **特征变换 (Transformation)**：侧重于调整数据的数学分布以适配模型假设。例如：使用对数变换处理长尾分布，使用归一化消除不同特征间的尺度差异。
- **特征选择 (Selection)**：目的是识别并保留高信噪比特征（即“去伪存真”）。例如：剔除多重共线性特征，依据重要性评分筛选关键变量。
- **特征约束 (Constraint)**：结合业务逻辑对特征值域进行合理限制（即“业务兜底”）。例如：将年龄限制在 0-120 之间，对超出统计范围的异常值进行截断。

### 1.2 边界

特征工程常与“数据清洗”混用，但两者关注点不同：清洗侧重保证数据质量与一致性，特征工程侧重把信息以更适合模型的方式表达。

以**缺失值处理**为例，两者在处理逻辑上存在本质区别：

- **数据清洗视角**：关注数据的完整性与程序的可运行性。通常采用均值或中位数填充，旨在修复“破损”的数据，防止模型因输入空值而崩溃。
- **特征工程视角**：关注缺失背后的业务含义与信息价值。例如，“用户拒绝填写”这一行为本身可能蕴含着高风险或特定偏好，因此不应简单掩盖，而应通过新增 `is_missing` 二值特征或填充特殊值（如 -1）来显式保留这一信息，供模型学习。

### 1.3 核心挑战与工程原则

特征工程不仅是算法设计的艺术，更是系统工程的试金石。为了确保模型从实验室顺利走向生产环境，必须严格恪守以下三大工程原则，以规避常见的“落地陷阱”：

1. **严防数据泄漏 (Data Leakage Prevention)**：所有特征统计量（如均值、分箱边界、Target Encoding 映射）的计算必须**严格限定在训练集范围内**。验证集和测试集应被视为“未来数据”，仅应用（transform）训练集得到的规则，严禁在计算阶段“偷看”全局信息，否则会导致离线指标虚高，上线即失效。
2. **确保训练-服务一致性 (Training-Serving Consistency)**：离线训练与在线推理必须共用同一套特征处理逻辑。任何实现层面的差异（如语言不通、库版本不同）都会引发**训练-服务偏差 (Skew)**。最佳实践是采用 Pipeline 序列化或引入特征存储 (Feature Store)，确保“逻辑一次定义，多处运行”，杜绝“线下 Python，线上 C++”带来的隐患。
3. **坚持可解释性优先 (Interpretability First)**：在模型收益微乎其微（如 AUC 提升 < 0.1%）时，应果断放弃复杂的黑盒特征（如高维 Embedding 交叉），转而选择物理意义明确的统计特征（如“近 7 天点击率”）。可解释性是业务归因、故障排查以及建立信任的基石。

## 2. 通用工作流 —— 从数据到特征的 6 步法

本章构建一套标准化的 6 步特征工程工作流。该流程旨在将经验驱动的“试错法”转化为可管理、可监控的系统工程，从源头的数据审计贯穿至最终的线上监控。完整链路如下：

1. **数据审计 (Auditing)**：全景扫描，识别风险。
2. **基线构建 (Baseline)**：确立下界，打通链路。
3. **假设生成 (Hypothesis)**：结合业务，提出猜想。
4. **变换实现 (Transformation)**：工程落地，严防穿越。
5. **评估归因 (Evaluation)**：多维校验，确认收益。
6. **监控迭代 (Monitoring)**：感知漂移，持续优化。

### 2.1 数据审计

数据审计是特征工程的“体检”环节，旨在在动手处理前建立对数据的全景认知。核心关注点应包含：

1. **完整性 (Completeness)**：识别缺失值的分布模式（随机缺失或系统性缺失），判断其是否蕴含业务含义。
2. **分布形态 (Distribution)**：通过直方图与 Q-Q 图检测数据的偏度（Skewness）与峰度（Kurtosis），识别长尾分布与潜在异常值。
3. **因果一致性 (Causal Consistency)**：严查“时间穿越”问题，确保特征产生的时间戳严格早于标签产生的时间戳，防止未来信息泄漏。

### 2.2 基线构建

基线的作用是确立模型性能的“下界”，并验证训练链路的连通性。在这一阶段，应优先使用逻辑回归或浅层树模型，配合最基础的预处理策略。

**工程最佳实践**：从第一天起就使用 `Pipeline` 封装处理逻辑。如下代码所示，通过 `ColumnTransformer` 将预处理步骤固化，从架构上杜绝训练与推理的数据处理不一致风险。

```python
from sklearn.pipeline import Pipeline
from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import OneHotEncoder, StandardScaler
from sklearn.impute import SimpleImputer

# 数值型特征处理流水线
numeric_transformer = Pipeline(steps=[
    ("imputer", SimpleImputer(strategy="median")),  # 缺失值中位数填充
    ("scaler", StandardScaler()),                   # Z-Score 标准化
])

# 类别型特征处理流水线
categorical_transformer = Pipeline(steps=[
    ("imputer", SimpleImputer(strategy="most_frequent")),  # 缺失值众数填充
    ("encoder", OneHotEncoder(handle_unknown="ignore")),   # One-Hot 编码，忽略未知类别
])

# 组合预处理器
preprocessor = ColumnTransformer(
    transformers=[
        ("num", numeric_transformer, ["num1", "num2"]),
        ("cat", categorical_transformer, ["cat1"]),
    ]
)

# 最终建模 Pipeline
pipeline = Pipeline(steps=[
    ("preprocess", preprocessor),
    ("model", ...),  # 后续接入分类器或回归器
])
```

### 2.3 假设生成

这一步是将“数据洞察”转化为“特征操作”的关键跃迁。高质量的特征假设通常源于两个维度：

1. **统计修正**：针对数据分布缺陷的数学调整。例如：数据呈现长尾分布 $\rightarrow$ 尝试对数变换（Log Transformation）；量纲差异过大 $\rightarrow$ 应用标准化（Standardization）。
2. **业务映射**：将领域知识编码为数值表达。例如：电商场景中用户对类目的偏好 $\rightarrow$ 构造“用户-类目”交互特征；文本场景中关键词的重要性 $\rightarrow$ 计算 TF-IDF 权重。

### 2.4 变换实现

在代码实现阶段，核心约束是**状态一致性**。特征变换可分为无状态（如对数变换）与有状态（如归一化、分箱）。

对于**有状态变换**，必须严格遵循 `fit`（仅在训练集计算统计量）与 `transform`（将统计量应用到所有数据集）分离的原则，确保验证集与测试集使用的是训练集的分布参数，而非其自身的统计量。

### 2.5 评估与归因

特征上线前的评估不能仅看 AUC 或 RMSE 的绝对涨幅，更需关注“收益来源”。建议采用两级评估体系：

1. **统计级评估**：检查变换后的特征是否符合预期。例如：归一化后的均值是否接近 0？分箱后的各箱样本量是否均衡？
2. **模型级评估**：通过特征重要性（Feature Importance）排序或 SHAP 值分析，确认新增特征是否被模型有效利用，而非仅仅引入了噪声。

### 2.6 监控与迭代

特征工程不是一次性工作，而是持续迭代的过程。模型上线后，需重点监控两类漂移：

- **特征漂移 (Feature Drift)**：输入数据的分布 $P(X)$ 随时间发生变化（例如：用户年龄层变迁）。
- **概念漂移 (Concept Drift)**：特征与目标的关系 $P(Y|X)$ 发生变化（例如：同样的“打折”在不同季节对销量的影响不同）。

一旦检测到显著漂移，即触发特征再工程或模型重训的信号。

## 3. 数值特征 —— 分布、尺度与非线性

数值型数据（Numeric Data）是模型最常见的输入形式。本章聚焦于三大核心问题：如何通过分箱引入非线性、如何通过幂变换校正偏态分布，以及如何通过尺度标准化优化梯度下降的稳定性。

### 3.1 二值化与分箱

本节讨论如何处理数值特征中的“非线性”与“噪声”。通过将连续数值离散化，我们可以牺牲一定的信息精度，换取模型对异常值的鲁棒性以及对非线性关系的拟合能力。

#### 3.1.1 定义与策略

二值化（Binarization）是将连续计数特征压缩为“0/1”信号，适用于该特征的存在与否比其具体数值更重要的场景。

分箱（Binning/Bucketing）则是将连续值 $x$ 映射为离散的区间索引 $b=B(x)$。它本质上是一种**非线性变换**，能够显著增强线性模型的表达能力。

**核心分箱策略对比**：

| **策略**         | **定义**                                       | **优点**                                                 | **缺点**                                                                     |
| :--------------- | :--------------------------------------------- | :------------------------------------------------------- | :--------------------------------------------------------------------------- |
| **固定宽度分箱** | 区间宽度相等。例如：[0-10], [10-20]...         | 计算简单，易于理解。                                     | **对长尾分布极不友好**。可能导致大部分样本集中在第一个箱子，而尾部箱子为空。 |
| **分位数分箱**   | 每个区间样本数大致相等（例如四分位、十分位）。 | **鲁棒性强**。能适应偏态分布，保证每个箱子的统计显著性。 | 箱宽不固定，业务解释性稍弱（例如“前 25% 的用户”不如“0-18 岁”直观）。         |

#### 3.1.2 为什么需要分箱？

1. **引入非线性**：线性模型 $y=wx+b$ 只能拟合直线。分箱后，模型可以为每个箱子学习独立的权重 $w_i$，从而拟合分段函数（Piecewise Constant Function），逼近任意非线性曲线。
2. **鲁棒性增强**：分箱能够吸收微小的测量噪声，并抑制极端异常值的影响（异常值会被归入两端的箱子，而不会拉偏整个回归直线）。

### 3.2 对数与 Box-Cox 变换

本节关注数据的“分布形态”。线性模型与神经网络通常假设输入数据服从高斯分布（Gaussian Distribution），而现实世界的长尾分布会破坏这一假设。通过幂变换（Power Transformation），我们可以“拉直”扭曲的分布，使其更符合算法的统计假设。

#### 3.2.1 定义

对数变换通过 $x'=\log(1+x)$ 压缩长尾分布。Box-Cox 变换 [2] 则是一族广义幂变换，旨在自动搜索最佳参数 $\lambda$ 以使得变换后的数据尽可能接近正态分布：

$$
x^{(\lambda)} =
\begin{cases}
\frac{x^{\lambda}-1}{\lambda}, & \text{if } \lambda \neq 0 \\\\
\ln(x), & \text{if } \lambda = 0
\end{cases}
$$

#### 3.2.2 直观理解

现实世界的数据（如电商销量、用户收入）往往呈现**长尾分布**（Long-tail Distribution）：绝大多数数值较小，极少数数值极大。

- **对数变换**：作用类似于“弹簧压缩”。它能剧烈压缩尾部的大数值，同时拉伸头部的小数值，从而缓解“方差随均值增大”的现象（Variance Stabilization）。
- **Box-Cox**：提供了更灵活的调节旋钮。$\lambda=1$ 为无变换，$\lambda=0$ 为对数变换，$\lambda=0.5$ 为平方根变换。通过最大似然估计（MLE）可自动寻找最优 $\lambda$。

### 3.3 标准化与归一化

本节解决特征间的“量纲差异”问题。当不同特征的取值范围相差悬殊时（如年龄 vs 收入），优化算法往往会陷入数值不稳定的泥潭。Scaling 是多特征融合建模的必要前置步骤。

#### 3.3.1 方法论

尺度处理（Scaling）直接影响基于距离的算法（KNN, K-Means, SVM）以及基于梯度的算法（Linear Regression, Neural Networks）。

| **方法**             | **公式**                                     | **适用场景**                                                   | **潜在风险**                                                                      |
| :------------------- | :------------------------------------------- | :------------------------------------------------------------- | :-------------------------------------------------------------------------------- |
| **标准化 (Z-Score)** | $x' = \frac{x - \mu}{\sigma}$                | **通用首选**。输出均值为 0，方差为 1。适合大多数机器学习算法。 | 不保证有固定的边界范围（输出范围可能是 $(-\infty, +\infty)$）。                   |
| **归一化 (Min-Max)** | $x' = \frac{x - x_{min}}{x_{max} - x_{min}}$ | 仅用于对输入范围有严格限制的算法（如图像像素需压缩至 [0,1]）。 | **对异常值极其敏感**。一个极端值会导致其他所有正常值被压缩到 0 附近，丧失区分度。 |
| **L2 归一化**        | $x' = \frac{x}{\|x\|_2}$                     | 文本分类、推荐系统。关注向量的方向（Cosine 相似度）而非模长。  | 丢失了模长信息（如“点击次数”本身代表的强度）。                                    |

#### 3.3.2 为什么必须做 Scaling？

1. **梯度下降加速**：若特征尺度差异巨大（如 $x_1 \in [0,1], x_2 \in [0, 10000]$），损失函数的等高线将呈细长的椭圆状，导致梯度下降呈“之”字形震荡，收敛极慢。Scaling 后等高线接近正圆，收敛最快。
2. **主成分分析 (PCA)**：PCA 寻找方差最大的方向。若不做 Scaling，方差大的特征将主导所有主成分，掩盖其他特征的变异。

### 3.4 交互特征

本节探讨如何突破“独立性假设”。大多数简单模型默认特征之间是相互独立的，而现实中特征往往存在协同效应（Synergy）。交互特征是显式捕捉这种非线性关联的低成本手段。

交互特征（Interaction Features）通过显式构造组合项（如 $x_1 \cdot x_2$）为线性模型引入非线性表达能力。

**核心价值**：简单的线性模型 $y = w_1 x_1 + w_2 x_2$ 无法解决 XOR 问题（异或问题），决策边界只能是直线。引入交互项 $x_3 = x_1 \cdot x_2$ 后，模型获得了拟合双曲线边界的能力，这是以极低的计算成本换取模型容量（Capacity）提升的经典手段。

## 4. 文本特征 —— 从 BoW 到 TF-IDF

文本数据是非结构化数据的典型代表。其处理核心在于将不定长的字符序列转换为定长的数值向量（Vectorization）。本章从最基础的计数统计出发，探讨如何通过 n-gram 捕获局部序列信息，以及如何利用 TF-IDF 识别关键词。

### 4.1 词袋与 n-gram

本节介绍基于统计的文本表示方法。这类方法假设文本的语义主要由其包含的词汇决定，而忽略语法结构。尽管简单，它们在垃圾邮件过滤、情感分析等任务中依然是强有力的基线。

#### 4.1.1 词袋模型 (Bag of Words, BoW)

词袋模型将文本视为词汇的无序集合。给定一个包含 $|V|$ 个独立词汇的词表，每一条文本都被表示为一个 $|V|$ 维的稀疏向量，向量的每个维度对应一个词的出现次数。

- **优点**：计算效率极高，保留了核心词频信息。
- **缺点**：**丢失词序**（“狗咬人”与“人咬狗”向量完全相同）；**维度灾难**（词表通常高达 10w+ 维，且极其稀疏）。

#### 4.1.2 n-gram 模型

为了在不引入复杂深度网络的前提下捕获局部词序，n-gram 将连续出现的 $n$ 个词视为一个整体特征。

- **1-gram (Unigram)**：单个词。如 "New", "York"。
- **2-gram (Bigram)**：相邻双词。如 "New York"。
- **3-gram (Trigram)**：相邻三词。如 "The New York"。

通过引入 Bigram，"New York" 不再是两个独立的词，而是一个具有特定语义的短语特征。这显著增强了模型的判别力，但也呈指数级增加了特征空间的维度。

### 4.2 TF-IDF

单纯的词频统计存在致命缺陷：常用词（Stop Words，如 "the", "is", "的"）频率极高但信息量极低，而真正的关键词往往频率较低。TF-IDF [3] 通过“惩罚高频”来修正这一偏差。

#### 4.2.1 算法原理

TF-IDF 由两部分组成：

1. **TF (Term Frequency)**：词项 $t$ 在文档 $d$ 中的频率。衡量词的**局部重要性**。
   $$ \text{tf}(t, d) = \frac{\text{count}(t, d)}{\text{total_words}(d)} $$
2. **IDF (Inverse Document Frequency)**：逆文档频率。衡量词的**全局稀缺性**。若一个词在所有文档中都出现，则其 IDF 趋近于 0。
   $$ \text{idf}(t) = \log \frac{N}{1 + \text{df}(t)} $$
    其中 $N$ 是文档总数，$\text{df}(t)$ 是包含词 $t$ 的文档数。

$$ \text{tfidf}(t, d) = \text{tf}(t, d) \times \text{idf}(t) $$

#### 4.2.2 案例计算

假设语料库有 1000 篇文档，词项 "machine" 出现在 10 篇文档中，词项 "the" 出现在 1000 篇文档中。对于一篇包含 2 次 "machine" 和 10 次 "the" 的文档（总词数 100）：

1. **计算 TF**:
   - $\text{tf}(\text{"machine"}) = 2/100 = 0.02$
   - $\text{tf}(\text{"the"}) = 10/100 = 0.1$
2. **计算 IDF**:
   - $\text{idf}(\text{"machine"}) = \log(1000/10) = \log(100) \approx 4.6$
   - $\text{idf}(\text{"the"}) = \log(1000/1000) = \log(1) = 0$
3. **计算 TF-IDF**:
   - $\text{tfidf}(\text{"machine"}) = 0.02 \times 4.6 = 0.092$
   - $\text{tfidf}(\text{"the"}) = 0.1 \times 0 = 0$

**结论**：尽管 "the" 的出现频率是 "machine" 的 5 倍，但其最终权重被修正为 0。模型成功识别出 "machine" 才是该文档的核心特征。

## 5. 类别特征 —— 编码与高基数

类别特征（Categorical Features）是描述离散状态的数据，如城市、品牌、IP 地址。与数值特征不同，类别特征没有天然的大小关系。本章核心解决两个问题：如何将非数值符号转化为数值向量，以及如何处理具有数百万取值的“高基数”（High Cardinality）特征。

### 5.1 编码策略概览

在工程实践中，编码方式的选择取决于类别的**基数**（Cardinality）和**模型类型**。

| **方法**             | **原理描述**           | **优点**                   | **缺点**             | **适用场景**                 |
| :------------------- | :--------------------- | :------------------------- | :------------------- | :--------------------------- |
| **One-hot Encoding** | 每一类一个二进制位     | 无损，无序假设             | 维度爆炸，稀疏       | 低基数（<50 类），线性模型   |
| **Feature Hashing**  | 映射到固定维度的哈希桶 | 空间恒定，无须维护词表     | 存在碰撞，不可逆     | 极高基数（百万级），在线学习 |
| **Target Encoding**  | 用标签均值代替类别     | 维度不增（1 维），强预测力 | **极易泄漏**，需平滑 | 高基数且强相关（如城市、ID） |

### 5.2 特征哈希 (Feature Hashing)

当类别数量达到百万级别（如 UserID）时，One-hot 编码产生的字典维护成本和内存消耗变得不可接受。特征哈希（Hashing Trick）通过哈希函数将任意输入映射到固定大小的向量空间 $m$。

$$ \phi(x) = \text{hash}(x) \pmod m $$

- **碰撞（Collision）**：不同的输入可能映射到同一个索引。这是为了换取空间效率而付出的代价。
- **有符号哈希**：为了减轻碰撞带来的偏差，通常使用带符号的哈希：$\phi(x) = \text{sgn}(\text{hash}(x)) \pmod m$。这样碰撞的特征可能会相互抵消（期望为 0），而不是一直累加 [4]。

**配套演示**：[05.05_Feature_Hashing.ipynb](../../feature-engineering-book/05.05_Feature_Hashing.ipynb) 展示了改变哈希空间维度 $m$ 如何影响碰撞率与模型精度。

### 5.3 目标编码 (Target Encoding)

目标编码（或称 Mean Encoding）是一种利用标签信息进行编码的强力技术 [7]。它直接用该类别在训练集上的**标签统计量**（如均值）来替换类别符号。

$$ \text{enc}(c) \approx P(Y=1 | X=c) $$

然而，直接计算极易导致**数据泄漏**（Data Leakage）和**过拟合**，特别是对于样本极少的类别。

#### 5.3.1 核心公式：平滑与收缩

为了降低小样本类别的方差，引入全局均值进行平滑（Shrinkage）：

$$ \text{enc}(c)=\frac{\sum\_{i: x_i=c} y_i + \alpha \cdot \bar{y}}{n_c + \alpha} $$

其中：

- $n_c$：类别 $c$ 的样本数。
- $\sum y_i$：类别 $c$ 的标签总和。
- $\bar{y}$：所有样本的全局均值（Prior）。
- $\alpha$：平滑参数。当 $n_c \ll \alpha$ 时，编码值趋向于全局均值；当 $n_c \gg \alpha$ 时，编码值由该类别的实际统计量主导。

#### 5.3.2 严防泄漏：基于折内的计算

工程实现必须严格遵守 **“看不见未来”** 的原则。最安全的做法是在交叉验证（Cross-Validation）循环内部计算编码值：样本 $i$ 的编码只能利用其所在训练折（Fold）的统计信息，绝不能包含其自身的标签。

```python
import numpy as np
from sklearn.model_selection import KFold

def target_encode_cv(values, y, n_splits=5, alpha=10.0, random_state=0):
    """
    基于交叉验证的目标编码实现。

    参数:
    values: 类别特征数组
    y: 标签数组
    n_splits: CV 折数
    alpha: 平滑参数
    """
    values = np.asarray(values)
    y = np.asarray(y)
    global_mean = y.mean()
    encoded = np.empty(len(values), dtype=float)

    # 核心：在 K-Fold 循环内计算，确保验证集（或当前样本）的编码不依赖自身标签
    kf = KFold(n_splits=n_splits, shuffle=True, random_state=random_state)
    for train_idx, valid_idx in kf.split(values):
        train_values = values[train_idx]
        train_y = y[train_idx]

        # 1. 统计当前训练折的 Sum 和 Count
        sums = {}
        counts = {}
        for v, t in zip(train_values, train_y):
            sums[v] = sums.get(v, 0.0) + float(t)
            counts[v] = counts.get(v, 0) + 1

        # 2. 对验证折样本进行编码（应用平滑公式）
        for i in valid_idx:
            v = values[i]
            s = sums.get(v, 0.0)
            c = counts.get(v, 0)
            encoded[i] = (s + alpha * global_mean) / (c + alpha)

    return encoded
```

## 6. 基于模型的特征构造 —— 降维与聚类

当特征维度过高或数据存在复杂的非线性结构时，简单的数学变换往往力不从心。本章介绍两种基于无监督模型的特征构造方法：利用 PCA 进行线性降维去噪，以及利用 K-means 构造非线性距离特征。

### 6.1 PCA：线性降维与去噪

主成分分析（Principal Component Analysis, PCA）通过寻找数据方差最大的正交方向，将高维数据投影到低维子空间。它不仅能压缩数据，还能去除特征间的共线性（Multicollinearity）。

#### 6.1.1 数学原理：方差最大化

PCA 的目标是在约束单位范数 $\|w\|_2=1$ 下，寻找投影方向 $w$，使得投影后的数据方差最大：

$$ \max*{w} \text{Var}(w^\top X) = \max*{w} w^\top \Sigma w $$

其中 $\Sigma$ 是协方差矩阵。该问题的解即为 $\Sigma$ 的特征向量（Eigenvectors）。前 $k$ 个主成分对应于最大的 $k$ 个特征值 [5]。

#### 6.1.2 工程实践：Pipeline 中的标准化

PCA 对数据的尺度极度敏感。如果一个特征的方差在数值上远大于其他特征（例如“收入” vs “年龄”），PCA 会由该特征主导。因此，**必须先进行标准化**。

```python
from sklearn.decomposition import PCA
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler

# 构建 PCA Pipeline：先标准化，再降维
pca_pipeline = Pipeline([
    ('scaler', StandardScaler()),  # 关键步骤：标准化
    ('pca', PCA(n_components=0.95)) # 自动选择组件数以保留 95% 的方差
])

# X_pca = pca_pipeline.fit_transform(X)
# print(f"降维后特征数: {pca_pipeline['pca'].n_components_}")
```

### 6.2 K-means 特征化：构造非线性距离特征

K-means 通常用于聚类，但在特征工程中，它是一种强大的**非线性特征构造器**。通过计算样本到各个簇中心的距离，我们可以将原始空间映射到一个新的“距离空间”。

#### 6.2.1 原理：径向基函数（RBF）网络

对于每个样本 $x$，我们计算它到 $K$ 个簇中心 $\{c_1, \dots, c_K\}$ 的欧氏距离，形成新的特征向量：

$$ \phi(x) = [\|x - c_1\|_2, \|x - c_2\|_2, \dots, \|x - c_K\|_2] $$

这种变换本质上类似径向基函数（RBF）网络。它利用 Voronoi 划分将非线性决策边界转化为线性可分的问题（Cover's Theorem），使得简单的线性模型也能处理复杂的分布 [6]。

#### 6.2.2 代码实现

```python
from sklearn.cluster import KMeans

# 1. 训练聚类模型
kmeans = KMeans(n_clusters=10, random_state=42)
kmeans.fit(X_train)

# 2. 变换：计算到簇中心的距离
X_train_dist = kmeans.transform(X_train)
X_test_dist = kmeans.transform(X_test)

# 3. 拼接：通常将距离特征与原始特征拼接使用
# X_train_new = np.hstack([X_train, X_train_dist])
```

## 7. 实战案例 —— 论文推荐系统的特征迭代

特征工程的最终检验标准是模型性能的提升。本章通过一个“学术论文推荐”的完整案例，展示**以数据为中心（Data-Centric）**的迭代流程：在固定模型算法（如逻辑回归）的前提下，仅通过特征工程的改进，实现预测效果的显著跃升。

### 7.1 阶段 1：构建基准（Baseline）

基准模型的作用不是追求高分，而是打通数据链路，确立评估底线。

#### 7.1.1 策略：最小可用产品 (MVP)

在第一阶段，我们采取“不做处理”或“最小处理”的策略：

- **数值特征**：直接使用（如年份），仅填充缺失值。
- **类别特征**：简单的 One-hot 编码。
- **文本特征**：不处理或仅做简单的计数（CountVectorizer）。

#### 7.1.2 快速实现

```python
# Baseline Pipeline
pipeline_baseline = Pipeline([
    ('features', ColumnTransformer([
        ('numeric', SimpleImputer(strategy='median'), ['Year']),
        ('text', CountVectorizer(), 'Title')
    ])),
    ('classifier', LogisticRegression())
])
```

**配套演示**：[09.01-05\_[End-to-End_Example]\_Recommender_Take_1.ipynb](../../feature-engineering-book/09.01-05_[End-to-End_Example]_Recommender_Take_1.ipynb) 展示了如何快速建立一个可度量的起点。

### 7.2 阶段 2：特征精炼与迭代

在基准之上，我们根据特征的特性引入领域知识和更复杂的变换。

#### 7.2.1 优化方向

1. **文本特征升级**：标题（Title）和摘要（Abstract）包含丰富语义。从简单的词频（BoW）升级为 **TF-IDF**，以降低常见停用词的权重，突出关键词。
2. **时间特征分箱**：年份（Year）直接作为数值可能存在非线性关系（如近期论文权重更高）。通过**分箱（Binning）**将其转化为类别特征，捕捉不同年代的趋势。
3. **高基数特征处理**：作者（Author）和会议（Venue）是高基数特征。利用**特征哈希（Feature Hashing）**或**目标编码**来压缩维度并保留信息。

#### 7.2.2 进阶实现

```python
# Enhanced Pipeline
pipeline_enhanced = Pipeline([
    ('features', ColumnTransformer([
        # 1. 年份分箱
        ('year_binned', KBinsDiscretizer(n_bins=5, encode='ordinal'), ['Year']),
        # 2. 文本 TF-IDF
        ('title_tfidf', TfidfVectorizer(max_features=10000), 'Title'),
        # 3. 摘要处理 (新增特征)
        ('abstract_tfidf', TfidfVectorizer(max_features=10000), 'Abstract')
    ])),
    ('classifier', LogisticRegression()) # 模型本身保持不变
])
```

## 8. 总结

特征工程是机器学习中“艺术与科学”的交汇点。它要求我们不仅要掌握数学变换（科学），还要深入理解业务逻辑（艺术）。

1. **数据决定上限**：无论模型多么先进，垃圾进（Garbage In），垃圾出（Garbage Out）。特征工程本质上是**将领域知识注入模型**的过程。
2. **简单胜于复杂**：在满足性能要求的前提下，优先选择可解释性强、计算成本低的简单特征。复杂的非线性特征（如深度学习自动提取）虽然强大，但往往伴随着更高的维护成本和不可解释性。
3. **迭代永无止境**：特征工程不是一次性的任务，而是贯穿于模型生命周期的持续迭代。从 Baseline 出发，通过误差分析定位问题，针对性地构造新特征，是提升模型性能最稳健的路径。

正如 Andrew Ng 所言：“Applied machine learning is basically feature engineering.”（应用机器学习本质上就是特征工程。）
